# Calque data

Everything the `seed.db` build reads lives here, so the build needs no network and no downloads.
`seed.db` itself is generated (`bazelisk build //app:seed_db_asset`) and is not stored in git.

| Directory | What | Source and license | Size |
| --- | --- | --- | --- |
| `seeds/` | Hand-written dictionary, false-cognate, lesson and cognate-rule seeds | Written for Calque | 100 KB |
| `subtlex/` | The 25,000 most frequent Spanish words with rank and count | SUBTLEX-ESP, CC BY-NC-SA 4.0 | 450 KB |
| `kaikki/` | Lemma entries, forms and aliases for those words, plus a list of seed words | Wiktionary via Kaikki, CC BY-SA 4.0 | 1.2 MB |
| `tatoeba/` | 20,000 Spanish-English sentence candidates with Tatoeba ids | Tatoeba, CC BY 2.0 FR | 750 KB |

Attribution for the third-party data is in [`NOTICE`](../NOTICE). The `subtlex/`, `kaikki/` and
`tatoeba/` files are **subsets of much larger downloads**, produced by the `extract-*` commands of
the preprocessor. They are regenerated by hand, rarely, when a newer dump is wanted; see
[`tools/preprocessor/README.md`](../tools/preprocessor/README.md) for the commands and
[`kaikki/spanish_lemmas.meta.json`](kaikki/spanish_lemmas.meta.json) and
[`tatoeba/spa_eng_candidates.meta.json`](tatoeba/spa_eng_candidates.meta.json) for the exact source
versions and counts of the committed files.

## Regenerating, in order

```
bazelisk run //tools/preprocessor:preprocessor -- extract-sublex   ...   # subtlex/
bazelisk run //tools/preprocessor:preprocessor -- extract-seed-words ...  # kaikki/extra_words.txt
bazelisk run //tools/preprocessor:preprocessor -- extract-kaikki   ...   # kaikki/
bazelisk run //tools/preprocessor:preprocessor -- extract-tatoeba  ...   # tatoeba/
```

`extract-sublex` goes first because the other two use its rank file to decide which words are in
scope. `kaikki/extra_words.txt` lists the words of the curated seeds so that they resolve in the
dictionary even if they are not among the 25,000 most frequent; regenerate it whenever the seeds
change. All outputs are deterministic: running a command twice gives identical bytes.
